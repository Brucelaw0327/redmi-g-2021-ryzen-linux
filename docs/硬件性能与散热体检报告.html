Linux 下怎么替代「小米游戏盒子」

GamingBox 是 Windows 专用程序（WPF + 驱动，走 WMI/EC），Linux 无法运行，Wine 也不行。 但这台机器的内核里已经有 redmi_wmi 与 bitland_mifs_wmi 两个驱动，常用的档位切换已经可以原生完成

功能Linux 现状说明
性能模式（Fn + K） 硬件支持 /sys/firmware/acpi/platform_profile Fn + K 可切换，但本机不使用按键，改由 perfmode.sh 直接写真实档位（见后文）
键盘背光 可用 bitland-mifs-wmi::kbd_backlight 亮度 0–3，直接写 brightness
风扇曲线 / 转速 不可用 驱动只暴露 fan1–3_input 且读数恒为 0，没有 pwm 接口
独显直连切换 不可用 MUX 由 EC/BIOS 控制，Linux 无对应工具，只能在 BIOS 里改
GPU 功耗墙 不可调 笔记本 vBIOS 锁死，nvidia-smi -pl 无效；当前 130 W 已是上限

切换档位（bench/perfmode.sh）—— 与硬件一致的三档：

档位platform_profile系统侧写入说明
静谧low-power powersave + power 最高频率硬封顶 3,201 MHz
均衡balanced-performance powersave + balance_performance 放开上限，日常与游戏主力档

./bench/perfmode.sh quiet      # 静谧
./bench/perfmode.sh balanced   # 均衡
./bench/perfmode.sh turbo      # 极速
./bench/perfmode.sh kbd 2      # 键盘背光 0-3
./bench/perfmode.sh show       # 查看档位、频率上限、温度、独显

档位只有三个，而驱动有两个 bug

把 BIOS 镜像反编译后可以确认：Setup 里只有一个「System Performance Mode」枚举项， 位于 SystemConfig（UEFI 变量 Setup）偏移 0x230，取值只有三个。 不存在第四档： 

@0x2714d6 [ONE_OF] prompt='System Performance Mode'
  help='Only silence/balance two kinds of mode are
        supported in battery mode.'
    * Turbo Mode    val=0000
    * Balance Mode  val=0001   <== DEFAULT
    * Silence Mode  val=0002

而 ACPI 声明了四个值。把 bitland-mifs-wmi 的 profile_set() 反汇编， 再逐值写入实测，三者的对应关系如下（0x230 直接从 efivarfs 读出）：

档位platform_profile 驱动写入 EC0x230实测
静谧low-power2 2 = Silence正常
均衡balanced-performance1 1 = Balance正常（修驱动后）
极速performance3 0 = Turbo正常（修驱动后）
平衡balanced0 0 = Turbo 假成功 返回 0 但固件忽略，实际落到极速

排查过程中定位到驱动里两个独立的问题，都已在本地修掉：

问题证据后果
AC 类型检查误判
bitland_check_performance_capability()		 CAP: system_supplied=1
CAP: AC type raw=0 (typec=1 circular=2)

修法只改一处：只在 EC 明确报告 Type-C 时才拒绝，未定义值放行，让固件自己决定。 保留「USB-C 供电不给满血」的原意，同时兼容返回 0 的机型。 

-	if (output.data[0] != WMI_SYSTEM_AC_CIRCULARHOLE)
+	if (output.data[0] == WMI_SYSTEM_AC_TYPEC)
 		return -EOPNOTSUPP;

补丁已做成 DKMS 包，重启后仍生效，内核升级会自动重编： 

cd bench/driver_fix
sudo ./install_driver_fix.sh      # 备份原模块 + DKMS 编译安装 + 验证三档
sudo ./uninstall_driver_fix.sh    # 需要时还原系统自带驱动

修好后三个真实档位全部对齐固件（写入 → 回读 → 0x230 三处一致）： low-power → 2、balanced-performance → 1、performance → 0。 注意两套编号顺序不同——驱动写的是 WMI 值（0=均衡/1=极速/2=静谧/3=满速）， BIOS 的 Setup 变量是 0=极速/1=均衡/2=静谧，混用会切错档。

KDE 三档：已打通

Plasma 的「省电 / 平衡 / 性能」不是 KDE 自己实现的：PowerDevil 的 powerdevil_powerprofileaction.so 只连 D-Bus 上的 org.freedesktop.UPower.PowerProfiles，真正干活的是 power-profiles-daemon。而 ppd 的中间档写的是 platform_profile = balanced —— 正是那个假成功的幽灵值。 所以即使驱动修好，直接用 ppd 依然会让「平衡」误落到极速。

解决方式是顶替 ppd 占住同一个 D-Bus 名字，把 KDE 三档映射到本机真实三档。 桥接服务实现了 ppd 的完整接口（HoldProfile / ReleaseProfile / SetActionEnabled 与全部属性），KDE 以为自己在跟 ppd 说话： 

cd bench/kde_bridge
sudo ./install_kde_bridge.sh      # mask ppd + 安装桥接 + 接管 D-Bus 激活入口
sudo ./uninstall_kde_bridge.sh    # 还原
KDE 档位实际写入 0x230governor / EPP
power-saverlow-power2 powersave / power
balancedbalanced-performance1 powersave / balance_performance
performanceperformance0 performance / performance

三档已逐档实测通过，链路是 KDE → D-Bus → 桥接 → platform_profile → EC → 固件 0x230，每一环都对得上。托盘、系统设置、「循环切换电源配置文件」快捷键 全部原生可用，不需要记 Fn + K，也不需要 perfmode.sh。

不要直接写 balanced：无论用 echo 还是别的方式， 它都会静默落到极速。要么走 KDE 三档，要么用 ./bench/perfmode.sh quiet|balanced|turbo（内部已映射到正确值并回读校验）。

需要注意的两点

  • CPU 此前被钉在最高频率运行（已解决）。体检时调频策略与 EPP 都是 performance，空载 8 核维持 4.4 GHz，空载温度就有 70–79 °C、风扇常转、离电续航偏短。 这属于设置问题，不是散热故障。现在由 KDE 三档接管（见上一节），切到省电档时 governor 与 EPP 一并变成 powersave / power， 实测同负载下温度下降 16–19 °C。 注意省电档会把最高频率硬封顶在 3,201 MHz，重载前记得切回「平衡」以上。
  • 独显的满载持续表现还没测。130 W 是功耗上限，能否长期吃住要看温度曲线。 在普通终端里跑 bench/gpu_watch.sh 600 再打开任意 3D 负载，把生成的 gpu_load.csv 交回即可补全这一段——这是最后一块空白。

结论

CPU、内存、存储的性能与散热都处在正常区间，且属于偏上水平，没有发现硅脂干涸、 散热模组失效、单通道内存或供电受限等老化/故障特征。独显功耗墙已确认是 130 W 满血规格，仅缺口在满载温度曲线。

  • 性能端：单核 139.8 GFLOPS 与 4.4 GHz 理论峰值 141 GFLOPS 几乎重合（达成率 99%）， 说明单核睿频能完整发挥；全核 1,058.6 GFLOPS 对应 4,135 MHz，已接近 Zen3 移动版 8 核的实际上限。
  • 散热端：7 分钟满载后温度稳定在 87–90 °C，且全核频率全程锁在 4,117 MHz 没有下滑， 说明散热能力足以长期吃掉满血功耗；如果散热模组衰退（积灰、硅脂老化），典型表现是 「温度顶到 100 °C 附近 + 频率逐分钟下滑 200–400 MHz」，这台机器完全没有这个现象。
  • 子系统：内存双通道约 43 GB/s（理论 51.2 GB/s 的 84%），SSD 顺序读写接近标称， 4K 随机性能正常，均无异常。
  • 可优化：峰值 93 °C 对 5800H 属于正常但不算凉快。若想让风扇更安静或温度再降 5–8 °C， 可考虑限制 PPT（如 ryzenadj --stapm-limit=45000）或清灰换硅脂； 日常轻载用 perfmode.sh balanced 即可，不必常驻极速档。
  • 独显端：功耗墙上限 130 W，与官方满血规格一致；轻载 66 °C 正常。 早前的 95 W 读数是性能模式限制，已排除硬件问题。只剩满载温度曲线待补。
测试方法：自编译 AVX2/FMA 吞吐程序（8 条独立依赖链饱和 2×256bit FMA 管线）、 STREAM 风格 triad、7-Zip 内置基准、OpenSSL speed、O_DIRECT dd、k10temp 每 3 秒采样。
CPU 功耗（RAPL）与风扇转速读数在当前环境下需要 root 权限 / EC 驱动支持，未纳入本报告。
独显满载测试：bench/gpu_watch.sh 600 —— 先启动它，再打开任意 3D 负载（游戏或 gpu-burn）， 600 秒后把 bench/gpu_load.csv 交回即可补全这一段。
